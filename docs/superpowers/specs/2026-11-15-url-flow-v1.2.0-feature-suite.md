# URL Flow v1.2.0 Feature Suite - Source Requirements

This document records the v1.2.0 scope supplied by the product owner on 2026-11-15.
Each phase has its own implementation plan under `docs/superpowers/plans/`.

URL Flow is a local-first Windows desktop app built with Electron, React and TypeScript.
All state lives in `%APPDATA%\URL Flow\url-flow-data.json`; there are no cloud
dependencies. A 40-step persistent undo/redo history backs every user change, and an
unpacked Manifest V3 Chrome/Edge extension ships in `browser-extension/`.

## Architectural guardrails

1. Every user-facing state mutation (auto-tagging, template instantiation, snapshot
   deletion, link URL replacement) flows through the existing undo/redo history pipeline.
2. `url-flow-data.json` stays lightweight. No raw HTML or multi-kilobyte Markdown is
   stored in it. External artifacts live in `%APPDATA%\URL Flow\snapshots\` and are
   referenced by ID or a boolean/timestamp flag in the JSON state.
3. `npm run typecheck` and `npm run build` must pass with zero errors and the
   `dist:local` / `dist:portable` packaging paths must keep working.
4. Source stays ASCII-safe, typed, and consistent with the existing light/dark theme
   tokens and keyboard-first UX (`Ctrl+K`, `Ctrl+N`, and so on).

## 1. URL tracker stripping and domain auto-tagging rules

- Create one canonical URL cleaner used during link capture (quick capture, browser
  extension, manual entry, bookmark import) and duplicate matching.
- Strip common tracking query parameters (`utm_*`, `fbclid`, `gclid`, `msclkid`,
  `mc_cid`, `mc_eid`, `ref`, `igshid`, `si`) while preserving functional parameters
  such as `?v=`, `?q=`, `?page=`.
- Normalize trailing slashes and default ports (`:80`, `:443`) for duplicate
  comparison without corrupting case-sensitive URL paths or queries.
- Add a `tagRules` array to settings in `url-flow-data.json`. Each rule is
  `{ id, pattern, matchType: 'domain' | 'regex', tags: string[], enabled: boolean }`.
- Add a Rules section in Settings to create, edit, toggle, test and delete auto-tag
  rules.
- Apply matching tags automatically whenever a link is captured or imported, merging
  with user-provided tags without duplicates.

## 2. Browser extension upgrades

- Add a `selection` context menu item `Save selection to URL Flow`. Pass the page URL,
  tab title and `info.selectionText` through the capture payload. In URL Flow's capture
  flow, pre-fill the link notes with the highlighted text as a Markdown blockquote
  (`> ...`).
- Add a toolbar popup (`popup.html` + `popup.js`) using
  `chrome.tabs.query({ currentWindow: true })` that can:
  1. save all open tabs in the current window as individual links, with optional tags;
  2. save all open tabs, or a specific Chrome/Edge tab group, into a new plan named
     after the group or a custom title, attaching every tab as a link in tab order.
- Handle batch payloads safely in Electron's deep-link/capture receiver, using chunked
  or encoded JSON, or a temporary local handoff file, when the payload exceeds Windows
  URL protocol length limits.

## 3. Offline readability snapshots and dead-link scanner

- Offline reader snapshot at `%APPDATA%\URL Flow\snapshots\<linkId>.md`.
- Install `@mozilla/readability`, `jsdom` (or `linkedom`) and `turndown` (or reuse
  existing main-process HTML parsing).
- Add a `Save offline snapshot` option to the capture dialog and to existing link
  detail cards, plus a global setting `autoSnapshotLinks: boolean` (default `false`).
- In the Electron main process, fetch the page HTML, extract article content with
  Readability, convert it to Markdown with Turndown, and write it to
  `%APPDATA%\URL Flow\snapshots\<linkId>.md` with header metadata (source URL, title,
  captured timestamp).
- Add an in-app reader modal/drawer for links with a snapshot: read cached content,
  copy Markdown, refresh or delete the snapshot. Remove orphaned snapshot files when a
  link is permanently purged.
- Add an IPC action to check link health with a concurrency-limited pool of 5 workers,
  an 8-second timeout, and `HEAD` with `GET` fallback. Classify results as `ok` (2xx),
  `redirect` (301/308 with the final destination URL) or `broken` (404, 410, 5xx,
  DNS/timeout error). Expose `Check Link Health` in the Links toolbar and the command
  palette, with status badges and one-click `Update to redirect URL` or
  `Archive broken link` actions.

## 4. Plan execution: templates, focus mode and launch-all-links

- Save any existing plan as a reusable template (`planTemplates` in
  `url-flow-data.json`), preserving summary, color, ordered steps (with relative day
  offsets instead of fixed dates), attached reference links and template tasks.
- Add `New Plan from Template` to the Plans view and command palette, prompting for a
  plan title and target start/end dates, then calculating step due dates.
- Add a split-pane `Focus Mode` toggle in the plan detail view. Left pane: summary,
  progress bar, ordered steps with one-click completion, and attached tasks. Right
  pane: attached links launchpad and quick scratchpad notes.
- Add `Launch All Links` on every plan and in the tray menu for pinned plans. It opens
  every non-archived link attached to the plan in the default browser, asking for
  confirmation when there are more than 8 links.
- Bidirectional `[[Wiki-Links]]`: typing `[[` in note and plan summary editors opens an
  inline autocomplete popover searching links, plans, tasks and notes. Render
  `[[id|Title]]` tokens in preview/read mode as clickable navigation chips that jump to
  the referenced item, and show a `Referenced by` backlinks section at the bottom of
  referenced items.

## Delivery phases

1. Schema migration, URL cleaner, domain auto-tag rules and Settings UI.
2. Browser extension selection capture, batch tab/tab-group capture, Electron batch
   ingestion.
3. Offline Readability Markdown snapshots, reader view, link health checker.
4. Plan templates, focus mode, launch all links, `[[Wiki-Links]]` and backlinks.

## Completion condition

`npm run typecheck` and `npm run build` pass, existing Vitest suites still pass, the
browser extension loads unpacked with the new menus and popup, and the v1.1.0 data file
opens in v1.2.0 without losing items, reminders or ignored matches.
